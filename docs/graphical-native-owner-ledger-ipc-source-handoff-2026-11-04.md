## Source work

`graphical_operation_owner_sqlite.ExistingOwnerLedger` is an explicit *existing-storage* SQLite successor to `SyntheticExternalLedger`. It will not create missing storage or populate first-seen approvals. A supplied independently selected scope/storage identity and highwater must match, with protected 0700 directory, 0600 lock file and SQLite database and inode checks. The owner obtains an exclusive lock shared by claims and revocation. It verifies the full original request digest and operation already in an independent preapproved map, records `CLAIMED_UNCERTAIN` in a `BEGIN IMMEDIATE`/FULL-synchronous SQLite transaction **before** invoking a source-injected sender, and retains the claim forever across sender exception/lost ACK/reopen. A subsequent result commit never frees the claim. Revocation serializes through the same exclusive owner lock; duplicate requests never invoke sender twice.

`graphical_operation_owner_ipc_admission` parses the exact **canonical** Host-deploy Task C `zog-graphical-owner-ipc-v1` frame with original GitHub repository/issue/actor, original request digest, separate original preflight vs stage operation IDs, selected stage/ordinal/binding digest/remote request digest and nonce. It authenticates the Linux Unix-stream peer via `SO_PEERCRED` and rejects caller substitution against an externally preselected original-GitHub record and full root-control operation request. It **only** returns `ORIGINAL_IPC_SOURCE_MATCH_ONLY`; it never sends or treats a matching payload as approval. A source fixture may supply the mapping; a native owner must get that mapping and operator signature from an independently installed authority, never gateway JSON.

Source tests cover separately constructed owner instances on one directory, concurrent duplicate claim and revoke, externally selected highwater denial, whole gateway rollback assumption, lost ACK, killed separate process after claim commit and before outbound send, wrong original GitHub issue/actor/stage/hash/operation, noncanonical frames and kernel UID mismatch.
