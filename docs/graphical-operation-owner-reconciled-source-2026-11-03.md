# Selected graphical operation send owner reconciliation — 2026-11-03

**Selected authority interface: PR #29's `SourceOnlyProtectedOwner` protocol**. PR #28's operator-signed, short-lived exact-claim authorization is retained as the independently pinned `verify_original_operator_approval` preadmission check. PR #28's alternative `claim_once` plus gateway-side SendCommand is **not** an admissible production sender and must not be implemented as a native fall-back.

1. The protected root-control owner preinstalls exact original operation ID → original SHA under authenticated Host, installation and STATE (plus current epoch, authority key, source/target, predecessor, stage-once, task and monthly pin) and denies a first-seen guess. A separately pinned operator signing key signs the exact request and scope, approval identity and bounded expiry. Approval validation does **not** mutate the owner ledger or authorize a direct send.
2. The same independent single-writer CAS/lock serializes send claim and revocation. The selected privileged owner durably commits irrevocable `CLAIMED_UNCERTAIN` before issuing the single owner-selected SSM SendCommand. Lost acknowledgements, crash, power loss, restored gateway volume and concurrent callers cannot issue a duplicate. A signed, nonce/highwater-bound observation is read-only and not redeemable for another command.
3. The gateway's existing `generic_pipeline.advance` → `host.submit_command` route must be removed/blocked whenever a protected graphical owner applies; no caller-supplied feature flag, old source pin or socket switch may restore it. Until native protected owner is installed, **fail closed, no SSM**. A synthetic test sender cannot be offered as a native RPC.
4. Native Work must prove an original installed signer and current-authority checkpoint, Host/installation/STATE/boot identity, immutable source/generation/task and predecessor, protected peer credentials, actual durable independently rollback-resistant ledger and pinned privileged sender with same serialized revocation. No source-only CI qualifies.

No source production pin, actual signing key, canonical STATE, AWS, SSM or native service is activated. All PRs remain drafts.
