# Task C selected trust model — shared administrative Host (2026-11-06)

**Model identifier:** `zog-graphical-shared-host-admin-trusted-v1`.

This model is selected for Task C's GitHub request intake, protected owner, and original Fonts compilation path. A single trusted administrative Host may operate the gateway, HTTPS webhook capture, operator/event issuance roles and protected owner. **An administrator controlling that Host is within the trust boundary and can administer the Host's SSM authority.** The system does not claim a separate physical security domain, nor promise that root can be denied access to local signing/owner credentials. A breached trusted Host is outside the asserted protection.

## Distinct responsibilities, not impossible administrator isolation

- **GitHub Actions OIDC**: an external, limited dispatch principal. Its selected AWS role must permit only the intended FIFO SQS submission actions to the exact queue and no SSM SendCommand, IAM PassRole, STS AssumeRole escalation, S3 owner-history mutation or compilation permission. The Actions job obtains this role only to send the validated request. Host administrative trust **does not** expand Actions permissions. Validate actual cloud IAM and issuer/audience/sub claims independently; workflow source alone cannot prove effective IAM.
- **Gateway program**: trusted to receive and validate requests on the shared Host. The *normal* graphical execution code path is `GitHub issue → GitHub Actions OIDC→SQS → host-deploy gateway → root-control protected owner IPC → protected owner claims/approval/history → SSM`. Preserve default fail-closed source routing that prevents a graphical operation from calling the legacy generic SSM helper before owner admission. A gateway **service identity** may have optional IAM/credential restrictions for defense in depth; this is not proof about what the Host administrator can do.
- **Protected owner**: remains the programmatic authority for exact original request and Host/installation/STATE binding; signed operator preflight/stage mapping, genuine GitHub event evidence, broker-purpose grant, irreversible monotonic send claim, cancellation/revocation and original S3 history verification. Must not resend after uncertain acknowledgement or rewrite historical genesis. Its selected owner SSM session and checkpoint-writer session remain explicitly named, separately constrained *roles/sessions*; they do not require separate physical machines or an administrator-inaccessible credential store.
- **Read-only trust broker**: remains a separately selected logical service with exact GetObject-only S3 session, original hash-linked S3 history/anchor, authenticated broker signer, real installed package/unit/pin and kernel peer identity. A missing/AccessDenied next sequence must HOLD and no ListBucket escalation is silently allowed. Broker and owner can share the trusted administrative Host but cannot substitute write authority for a read-only broker credential in the normal code path.
- **Operator and event issuer**: use distinct domain-separated signatures, separately enrolled public pins, explicit operator consent, genuine raw original GitHub webhook HMAC and independent original signed records. Logical role-scoped protected credential **views** and exact source mounts can coexist on one trusted Host. The source check refusing an opposite-role private key in a signer's own view remains meaningful; it does not establish inability of root to reach both keys. The original event receipt cannot be fabricated or retroactively reissued from a mutable API snapshot.
- **Webhook capture**: may run on this same trusted intake Host under a dedicated service user behind authenticated HTTPS; secret and raw receipt confinement are program-level protections and an audit aid, not defenses against the trusted Host administrator.

## Mandatory acceptance versus optional defense in depth

**Mandatory for a graphical operation:** exact accepted installed source and installed Python/wheel RECORD and unit hashes; correct root/STATE identities; original operator approval and issuer evidence (or separately authorized new request), exact queue/role/Host and catalogue; independent-from-gateway rollback persistent claim history and original S3 genesis/anchor verification; protected owner IPC peer identity and per-operation claim/revoke serialization; no second send after uncertain result; actual owner SSM session identity/capability, and signed read-only broker history. A trusted administrator must still use the reviewed normal owner workflow for authorized Fonts execution; the model does not endorse bypassing claims.

**Optional evidence, not a shared-Host GO/NO-GO condition:** proof that a gateway *service principal* cannot independently invoke SSM or acquire owner credentials/IMDS. These checks are advisable when separate service sessions exist. They must not be generalized into a requirement to prove the trusted **Host administrator** has no direct SSM access. An administrator can change systemd, process credentials, IAM session sources, namespace or root-owned files on their own trusted Host. A direct route blocked by application code is a useful fail-closed invariant, not a proof of Host-level IAM isolation.

**Never enough by themselves:** an IAM-denial JSON fixture; a signed approval with no original source; a source-only unit contract; a synthetic GetObject-only AWS session; a protected mount on the *same Host* claimed to resist that Host's administrator; passing CI from a made-up gateway actor. Native evidence must report real facts, and cannot turn held authority into accepted authority by setting Boolean fields.

## Exact source selection and owner handoff

The shared-Host model changes **security claims and native acceptance wording**, not established original source SHA/role selection or runtime admission flags. Retain the already reviewed root-control original owner PR #39, root-control broker provider PR #40, host-install disabled owner/broker PR #32 and host-deploy protected owner PR #26; do not silently repin immutable source, change S3 account/region/bucket/prefix/genesis/writer-role, start the broker/owner or send graphical SSM.

**Host-install Regular**: distinguish optional gateway service-principal denial policy from mandatory authenticated owner role, original history, separate logical sessions, per-operation claims, and selected service/IPC bytes. Remove native acceptance demands to prove a root administrator cannot reach SSM. Keep negative tests for accidental direct software route if useful.

**Host-deploy Regular**: retain gateway→owner→SSM dispatch in generic pipeline; never route graphical capability probe, producer preflight or legacy runner directly around owner. Confirm Actions OIDC role is SQS-dispatch-only (actual IAM verified by Work) and do not infer admin isolation from source-route tests.

**Root-control Regular/Work**: preserve original approvals, event HMAC, signer/pins, writer and read-only role boundaries, revocation and nonrollbackable history with explicit same-Host administrator limitation. If historical original issuance does not exist, require separate approval for a genuinely fresh GitHub issues.opened Fonts request. Verify real current installed evidence; do not generate substitute historic grants or checkpoint records.

## Disposition

This is **source trust-model reconciliation**, not Work's physical or IAM acceptance. No production source pin, credentials, Host profile, workflow OIDC role, original checkpoint, service status or SSM send changes are authorized here. A single trusted Host is sufficient for the intended threat model; the normal owner-controlled execution and accountably verified original operation are still required.
