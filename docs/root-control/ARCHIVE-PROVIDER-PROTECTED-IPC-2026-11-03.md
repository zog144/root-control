# Root-control archive provider protected IPC source handoff · 2026-11-03

**No live activation.** This branch is a separately reviewed root-control **interface handoff**, not an implemented receiver or process. Its exact host-install companion source is `59a2e99c877c2687a01e69cd026d0966a2631afd` (draft PR #22), archive-mirror `9df811cf9315efec4312e6a16738a23149d286a2`, and host-identify `59dbc181f54c6ac29ee5eb1f83b6f322fb73c037`.

`project/archive-provider-ipc-source-handoff-v1.json` retains `archive_app_uid=null`, `archive_app_gid=null`, `authentic_native_witness=null`, `native_accepted=false` and `activation_allowed=false`. The source tests reject filling those fields with guessed values or selecting an issuer/Cloudflare profile. This is a source gate, **not** a reversible production feature flag.

## Intended native owner boundary

1. Root-control must independently validate and pin the original Host identity, installed rootfs, installation, protected STATE mount, application UID/GID, archive scope and exact Credential Authority public key. It must not inherit station-access, Cloudflare issuer or host-discover keyring authority.
2. A future dedicated root-control command connects to the selected archive-mirror application process over an authenticated AF_UNIX stream whose peer PID/UID/GID are verified using SO_PEERCRED and matched to independently provisioned service identity. A socket pathname alone is not identity. The dedicated socket identity must never alias `/run/zog/root-control.sock` or an issuer broker socket.
3. After an authenticated, current signed archive-specific grant and one-time nonce/delivery are committed, the receiving owner must durably claim `installing` **before** transmitting exactly one sealed anonymous credential FD with SCM_RIGHTS. No secret in argv, environment, JSON, journal or receipt. Both sides must dispose of unexpected/extra FDs on denial. The source-test host-install module checks only Unix peer/FD predicates; **root-control does not yet implement this transfer**.
4. The selected nonroot archive application, not the root caller, owns its protected 0700 private state and 0600 credential installation. The actual existing consumer takes `secret` in a verified delivery dictionary; a new application-owned FD adapter is still needed to avoid decoding and rewriting secrets inside root-control. No future system should import the synthetic in-process bridge as the IPC adapter.
5. On crash, missing acknowledgement or mismatch, **no redelivery**. Recover from current signed authorization and protected application-owned inspect + installed-byte attestation. A receipt must bind Host/installation/STATE/collection/credential/authorization/UID/GID/request/delivery to an independently authenticated application response and root-control ledger. Native verification must assess actual byte equality, provenance and storage durability; it cannot accept a caller-selected `witness_valid=True`.
6. Root-control commits signed revocation into common deny first, then invokes the archive process's separately signed application tombstone operation (no FD). If the application response is lost, only identical revocation reconciliation is permitted. Archive catalogue, retained objects, downloads and pins must remain untouched.

The current CI verifies immutable source pins, the disabled contract and host-install's peer/FD/checkpoint API shapes, with extensive negative cases for unauthorized UID/GID selection, wrong consumer purpose, activation and invented native witnesses. No service unit, protected socket, application-process harness, real key, STATE or credential transfer has been created.

**Disposition:** source contract ready for native implementation design; actual IPC implementation, operator authorization, protected installation and reboot acceptance remain NO-GO under archive-mirror issue #2.
