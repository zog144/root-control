## Audited source-level escape

The earlier reviewed root-control `97481da26ae1294c9bf474f93f2ed90b4512b9b1` explicitly sends finite worker `StandardOutput=journal` and `StandardError=journal`, with **no** `LogNamespace`. Its worker slice is correctly a child of the host-deploy cancellation parent, but **cgroup placement does not govern where host journald stores its files**. systemd puts normal output in the host default journal, outside both preallocated quota images. Thus any statement that the source-fixed slice alone enforces a 32-GiB total additional-host-disk allowance would be unsupported.

systemd 252 supports a per-service `LogNamespace=`, which selects a distinct `systemd-journald@<name>.service` instance and distinct persistent/volatile journal files. However **`LogNamespace=` alone is routing, not storage/quota confinement**: normal persistent namespace storage is below `/var/log/journal/<machine-id>.<namespace>`, and it may initially use `/run/log/journal`. The systemd-journald@ service's `LogsDirectory=` can create paths even where the operator configured volatile storage. The approved 2-GiB pool's directory named `systemd-journal` does not magically redirect these paths.

## Exact root-control successor: fixed fresh-only worker namespace

New `root-control` successor on `unstable` retains the existing fixed parent/child and `build-only-project-v1` restrictions, but for **only** the protected `fresh-cross-bootstrap-oct25` Project additionally freezes:

- **`LogNamespace=zogfreshcrossbootstrapoct25`**, immutable source constant, submitted through typed D-Bus `StartTransientUnit` to every finite worker service. Worker `StandardOutput=journal` and `StandardError=journal` are unchanged.
- The **build-log reader** now derives the same fixed namespace from the privileged daemon role and passes `--namespace=zogfreshcrossbootstrapoct25` to bounded `journalctl`; callers cannot supply their own namespace. A namespaced log-page cursor is cryptographically scoped to that namespace as well as the saved boot/InvocationID. Default historical and application log readers remain unchanged.
- The namespace is also durably bound into the privileged resource registration and each prepared job **before any build start**. Repeated preparation, inspection, registration status and release refuse a missing/different namespace; old unscoped Projects retain their old record formats and default journal behavior.
- `build_observe` compares exact manager `Service.LogNamespace` plus stdout/stderr properties against the saved approved values. A missing/wrong namespace, even when `Slice` and `ControlGroup` are correct, is an integrity fault. Existing source tests cover mismatched PID1 readback and durable record tampering.
- The optional historical root-control journal-barrier broker currently runs `journalctl --sync` without any namespace selector. **The fresh sidecar fails closed if `ROOT_CONTROL_JOURNAL_BARRIER=1`, before starting that broker**, and the build backend rejects an injected unscoped broker. It must not claim worker namespace log durability from an unrelated default-journal synchronization; implementing a true namespace-aware broker needs a separate review, including its own root-owned state inside the 2-GiB pool. Absence of a barrier means the ordinary systemd result must be independently observed and preserved; any vanished/uncertain unit stays blocked, never fabricated successful.

This source change does **not** add generic privileged logging RPCs, grant a caller-chosen namespace, permit alternate journal paths, change non-fresh shared daemon behavior, modify the original `ExecStartEx` job, or remove host-deploy's fail-closed `journald-namespace-unverified` gate.

## Mandatory native installer and filesystem contract (host-deploy owner)

Before any fresh compiler start, native Work on an **approved disposable systemd/Linux boundary using the already authorized resources** must prove:

1. **Quota geometry and mount ownership:** audited root-owned 30-GiB worker ext4 + separate 2-GiB external ext4 are the only new budget pools. Both backing files are fully allocated, retained after reboot, and combined *host allocation including metadata/slack* does not exceed 34,359,738,368 additional bytes. Account for fixed entries outside these images (mountpoints, device nodes, cron definition, transient PID1 metadata) without assuming negligible = free.
2. **Exactly bound journal namespace:** external pool already mounted before any new `systemd-journald@zogfreshcrossbootstrapoct25` socket/service is activated. Verify PID1 really honors `LogNamespace` with `busctl`/unit properties and `journalctl --namespace=zogfreshcrossbootstrapoct25`; verify all new worker stdout, stderr and native journald/syslog messages are in that namespace, not copied into the default journal. Include post-`daemon-reload` evidence **only inside a disposable PID1**, not the retained shared host.
3. **Actual journal file backing:** determine the target systemd 252 namespace's exact `/var/log/journal/<machine-id>.<namespace>` persistent path and any `/run/log/journal` fallback, along with `systemd-journald@...` template `LogsDirectory`, tmpfiles and early activation behavior. The protected host installer must mount/bind or otherwise direct *all actual journal-file backing* to the bounded external ext4 **before activation**, with read-only identity of mounted source and hard allocation quota; verify `stat.st_dev`, `findmnt`, `/proc/<PID>/mountinfo`, inode owners, `journalctl --flush --namespace=...`, `journalctl --sync`, and actual journal file growth against quota. Refuse unbounded volatile storage, hidden default-directory writes or a namespace mount recreated on reboot outside the budget.
4. **Controller, watchdog and PID1 logs are separate:** a worker `LogNamespace` does not capture logs emitted by the privileged root-control sidecar, host-deploy installer, watchdog, timer, cron, PID1 service lifecycle, default journald, SSM or kernel diagnostics. Each fresh-specific writer must be explicitly routed into the bounded external pool or accounted for with a defensible, enforced aggregate allowance. The systemd manager's own messages may remain in **default** host journal even for a namespaced worker; do **not** certify total accounting solely by observing namespaced stdout/stderr.
5. **Every mutable mount and evidence path:** independently inspect the actual worker mount namespace, rootfs, source/output, private /tmp and /run, registration directory (default root-control `/var/lib/zog/build-resources`), host owner ledger, image-build spool, transient-unit fragment directory, core dumps, crash traces and journald runtime/persistent files. Every newly writable persistent class must be bounded/accounted within the 30+2-GiB budget, or **block**. A class name in `fresh_aggregate_disk.py` without matching kernel backing is not admission evidence.
6. **Fail closed under failure and reboot:** force heavy interleaved stdout/stderr/native journal traffic until the bounded namespace journal filesystem fills; demonstrate no fallback to unbounded default/volatile paths and that the fixed fresh-only cancellation guard still stops all descendant PIDs. Stop/restart the journald namespace, reboot the disposable PID1, lose cron and watchdog concurrently, lose external mount, and prove the admission watchdog/independent 21,600-second timer blocks or safely stops exactly the fresh operation. Preserve the old shared controller and historic `bad-setting` fragment and source/record hashes throughout.

**Important:** file-system redirection and namespaced journal configuration are **host-deploy/host-install protected installer work**, not a root-control RPC. The root-control source asserts *where systemd should route fresh worker streams*, but does not create any host mount or assert journal allocation success. The installer/native inspector must retain `journald-namespace-unverified` until independent measurements establish the complete disk/logging bound; otherwise the user-approved new cross-bootstrap is **NO-GO**.
