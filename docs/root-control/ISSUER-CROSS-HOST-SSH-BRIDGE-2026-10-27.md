## Work performed

Added explicit new `python -m zog.root_control.issuer_cross_host` actions:
- `client-transfer --project <exact-project>`: independent root-only approval+reader projection check, installed host owner-receipt digest and station signer pin digest, root-owned exact SSH identity and single Ed25519 known-host line, fixed hostname/port/account, SSH transport with no TOFU/password/agent/proxy/forwardings/user config/PTY, canonical bounded one-shot request, bounded raw token, fresh second owner check, anonymous pipe and existing `issuer_credentials.install_from_fd`. It does **not** change the legacy local `issuer_station_transfer transfer` action.
- `ssh-bridge`: dedicated *unprivileged* transport principal, fixed SSH_ORIGINAL_COMMAND, bounded canonical stdin and stdout, protected station broker AF_UNIX endpoint with root socket mode/peer UID validation. This does not authenticate the SSH public key itself; sshd must enforce exactly one separately approved key -> exactly one dedicated UID. The key cannot be learned from request JSON.
- `station-broker`: privileged service accepting inherited fd3 *only* at `/run/zog/issuer-cross-host-broker.sock`, exact root:bridge-gid 0660 inode/type, SO_PEERCRED dedicated bridge UID/GID, separately protected `cross-host-station.json`, exact Host/install/assignment/revision/receipt/approval binding, checked station protected projection, durable root-owned per-key/per-approval/per-nonce O_EXCL and fsync barrier before decrypt, separate nonce for the existing **local** station vault reader, and independent authorization recheck before token emission. Failure emits no application diagnostic to client. This is NOT a station web view, SSM command, or root-control generic daemon RPC.

The wire schema has exactly:
`schema=zog-station-issuer-cloudflare-cross-host-v1`, `operation=read-approved-cloudflare-issuer-token`, `authorization_id`, `host_id`, `installation_id`, `assignment_id`, `assignment_revision`, `receipt_sha256`, `nonce`. Canonical ASCII JSON plus newline, total at most 1024 bytes. Remote request cannot choose UID, storage path, Cloudflare account, arbitrary SSH command, hostname, zone or credential.

The client root-only per-project file is
`/etc/zog/issuer-credentials/<sha256(canonical project path)>.cross-host-client.json`, mode 0600, owner root:root, with exact schema `zog-issuer-cross-host-client-v1`, project/approved assignment identity, Host/install/STATE/fingerprint/registry, pinned SSH endpoint and exact key files/hashes, root owner-ledger SHA-256 and independently installed station signing-pin SHA-256. The source verifies the protected owner receipt at `/state/host-install/certificate-owner-authority/authority.json` and installed signing pin at `/etc/zog/host-install/certificate-assignment-authority.json` on **each** call before and after remote retrieval.

The station root-only binding is `/etc/zog/issuer-credentials/cross-host-station.json` (schema `zog-issuer-cross-host-station-v1`, mode 0600), including independently assigned unique SSH bridge UID/GID, reviewed SSH transport key fingerprint, exact approved Host/install/STATE/fingerprint/registry/assignment/revision/receipt/authorization identity, local station projection and reader UID/GID, and durable nonce directory. Its key-fingerprint field is an *expected identity from sshd provisioning*; proving that the local UID actually corresponds exclusively to that key is a **separate native hard gate**.

The station vault reader retains its original local SO_PEERCRED(root) checks, current ManagedDns01Hostname grant selection, session/revision/revocation, independent read nonce and post-decrypt freshness checks (station-access PR #8). No network socket is exposed directly from the vault reader.
