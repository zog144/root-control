# Unified protected HTTPS issuer receiver — 2026-10-29

**SOURCE-ONLY REVIEW. No live token transfer, certificate operation or retained Host mutation.**

This supersedes the SSH-specific receiver proposal from root-control PR #13 and host-install PR #5. The Credential Authority is the Command-Center Host; the receiver is an independently Enrolled Host. The protected station vault's local reader, the issuer grant and certificate-data storage, and the privileged anonymous-FD installer remain separate.

The root receiver is the explicitly selected root-owned Python operation zog.root_control.issuer_https_receiver.receive_and_install, not a generic root-control daemon RPC. It is opt-in and requires prior native owner admission. An installed reviewed HostIdentity signer, not a request body, signs a bounded POST using the existing Zog RFC 9421 Ed25519 Host signature profile. The endpoint is fixed at /api/hosts/credential-delivery/v1/receive/ on protected HTTPS port 443. Redirects, proxies, credentials in URLs and alternate ports are rejected.

The protected client profile schema is zog-issuer-https-credential-client-v1, matching the existing host-deploy certificate_cross_host_admission consumer contract. Its root-owned per-project file binds exact Host/installation/STATE/HostIdentity, registry, signed assignment/revision/receipt, current local authorization, credential revision, consumer UID, grant/storage, independent owner receipt and signer-pin byte hashes, HTTPS origin, and pinned CA bytes. Its purpose is issuer-cloudflare-dns01 only. Station CA verification and a separately pinned station Ed25519 response key are both required.

A durable one-time nonce record is fsynced before the first HTTP request. A timeout, crash or cancellation never blindly resends it. A full canonical JSON signed response is required, with identical request hash and nonce, Host/installation/STATE, registry, authorization, assignment/revision/receipt, credential UUID/revision, grant/storage/policy, approved consumer UID and expiry. Ed25519 signature is over the domain-separated response JSON excluding the signature. Raw token bytes are decoded only after signature validation, passed by anonymous pipe to the existing root-controlled issuer_credentials.install_from_fd, and never returned in an audit, CLI output, journal or generic controller call.

**Producer coordination:** This source proposes a response schema zog-protected-credential-response-v1, but the Command-Center Host has not yet implemented or approved a matching signed HTTPS endpoint. Station-access and host-identify must jointly confirm the exact interoperable protocol and durable server replay before any native activation. Do not infer that a signed beacon or inspect-only session grants credential access.

**Remaining installation/acceptance gates:** host-install source and wheel RECORD attestation, independently trusted HostIdentity consumption and station CA/pin, current owner/STATE/second-ledger/projection checks, destination grant and credential revision, host-deploy delivery policy, protected native receiver admission, expired/revoked authority denial, TLS and signature substitution, truncated/partial stream, crash/reboot nonce persistence and zero token leakage. Source CI cannot constitute those gates. Default native_https_accepted remains false.

**Explicit exclusion:** original RF5BGA preparation/abandonment is a separate operation needing its own authorization; neither SSH nor HTTPS source work retries it. No retained issuer, STATE, EC2, DNS, ACME or nginx change was made by Regular.
