## Implemented source path
- `TaskCExecutor` now selects the **independently operator-signed original GitHub issue/actor/request hash** through the root-installed registry, and maps the fixed immutable request and approval to separate preflight and stage IDs. The incoming gateway frame carries only lookup hints, never SSM target, shell, AWS credentials, approvals or arbitrary authority.
- Both operations go through the same root-only serialized `ProtectedLedger` with external conditional append-only S3 claim **before** any selected fixed `SendCommand`. An uncertain S3 ACK, local fsync failure, SDK timeout or unknown SSM result cannot reopen the original claim. `total_max_attempts=1` remains selected for both SSM send and S3 conditional create.
- A stage **cannot** claim/send until its *distinct*, originally approved preflight has an irreversible result and original `GetCommandInvocation` readback for its fixed instance reports `Status=Success, ResponseCode=0`. A separate read-only `observe-original` action permits an eventual result without sending again. Failed, pending, uncertain and revoked preflight denies the stage.
- Responses are fresh, nonce-bound Ed25519 **v2 signed observations** bound to original request SHA, scope, Host, installation, STATE, authority epoch, operation ID, command ID, verified SSM state, and the **fresh external S3 checkpoint sequence and hash-linked history head**. The native Task C executor rejects the legacy local file-only checkpoint backend even when its files appear durable. They are not reusable send grants. A failed stage yields `stage-failed`, never `stage-succeeded`; a stage's SSM success still does not prove image-generation acceptance. The previous **unsigned v1 gateway must reject this v2** until host-deploy selects its verified consumer.
- `graphical_task_c_origin` additionally verifies a separate, installer-pinned Ed25519 GitHub-event issuer and a finite-lifetime source receipt whose original issue, actor, request hash and derived preflight sibling match the root-signed operation mapping. Root-control does not mint a receipt or regard an arbitrary SHA field as independent authority; Work must establish genuine event provenance and issuer custody.\n- `graphical_task_c_native` loads root-owned immutable-looking installation source, protected operator pin and observation private key, checks exact Host/STATE/boot/mount/source constraints, constructs distinct explicit short-lived *checkpoint S3 role* and *SSM send role* sessions, checks each real STS assumed-role identity and no shared access key, pins genesis, and constructs the fixed sender, ledger, inspector and selected `AF_UNIX SOCK_STREAM` service. It cannot create genesis, invent a signed approval or select a default credential chain.
- The stream service source now routes its authenticated, bounded canonical frame into that exact runtime rather than an eternal source-only read. Kernel `SO_PEERCRED` and a source-level procfs starttime/cgroup/executable witness are required; host-install/Work must independently attest executable bytes, invocation, actual peer and current policy.

## Activation / native GO is **not** part of source work
The installed `main()` entry point **continues to refuse startup** with `NATIVE_TASK_C_SEND_ADMISSION_IMPLEMENTED=False` before credentials, socket or AWS. That hard gate cannot be flipped by a runtime JSON boolean. No unit, signer, original operation, retained STATE, genesis, AWS identity or live SSM command is fabricated or activated.

Outstanding independent native gates: authoritative GitHub origin evidence custody, trusted current operator/owner signer and source+wheel RECORD pin; actual current Host/STATE and gateway cgroup/InvocationID; protected role sessions; scope-pinned genesis, bucket/authority policy and fully surviving history; effective gateway UID credential/IMDS/STS/SendCommand denial; no owner private credential exposure; original preflight status readback and stage send; kill/lost ACK/revocation/rollback/reboot acceptance. Existing administrator/owner-role S3 policy tests prove only the checkpoint component. The current shared Host role remains unchanged.
