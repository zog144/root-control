# Independently protected graphical operation send fence — source contract

**2026-11-03 · Source-only design, NOT an installed authority or worker.**

## Scope and original problem

Host-deploy PR #18 (source head `c39db615718733084f0eb330b3e37cbb60e4db45`) adds an exclusive 0600 local gateway send-intent and original SSM CommandId receipt. Its 234 tests convert the prior whole-journal replay and forged snapshot XFAIL into passing source-level denials. The local files **cannot** survive an attacker/coherent backup rollback of the entire gateway-owned storage domain. Host-deploy issue #17 remains open.

The existing root-control PR #24 `graphical_monotonic_issuer` (head `9036c98e8af6469a17e8fcc31e1a40795330ee48`) covers **current signing-key checkpoint epochs**, not independent individual SSM operation claims. The operation owner must use a distinct domain-separated ledger and immutable signing authority. Do not conflate the key-rotation sequence with per-operation history.

## Model delivered

`src/zog/root_control/graphical_operation_owner_source.py` defines a source-only protocol and test fixture:

- **Exact immutable request** — Host, installation and STATE volume 64-hex IDs; managed lane and only the current three Fonts/XCB/X11 reviewed task names; SHA256 of selected catalogue, monthly source pin, predecessor receipt, original request, protected stage-once receipt and full remote request; exact source commit, base generation, operation ID, phase and ordinal; current signing-authority epoch and independently pinned authority/approval digests. No Mesa/LLVM/Xvnc task admission is added.
- **Original history first** — the simulated independent owner is pre-provisioned with the exact original operation-ID-to-full-request-SHA mapping; it rejects unapproved new operation IDs and changed digests. The gateway may not ask the issuer to infer approval from syntactically well-formed first-seen JSON.
- **Linearizable irrevocable claim** — under one independent critical section shared with revocation, verify current scope and original history, commit the exact operation claim `CLAIMED_UNCERTAIN` first, and invoke exactly one **owner-selected protected** SSM sender. Later retries, including identical requests, alternate input, crash and a gateway-volume restore, cannot issue another command. If SSM returns a true original CommandId, append its proof while keeping the original claim. If reply is lost or completion uncertain, HOLD and reconcile original invocation independently; never free the claim.
- **Revocation** — revoke the exact current scope in the same independent lock/transaction as claim/send. After revocation commits no new send can start. An already initiated SendCommand precedes the committed revocation; cleanup/cancellation is a separate separately authorized action, not implicit replay. Reboot sees the external highwater and original claim, not a reconstructed gateway-local `prepared` state.
- **Signed observation (not a send ticket)** — Ed25519 domain-separated `zog-protected-graphical-operation-observation-v1` over current scope, operation, irrevocable sequence, revocation status and fresh 48-hex nonce. The source verifier requires an independently pinned key digest and minimum external sequence; wrong Host/installation/STATE, altered remote request, stale/foreign signature or nonce, and revoked status cannot be read as a new send permission. No response contains a redeemable send token.
- **Tests** — source synthetic external ledger remains outside the mock gateway data, including across simulated restart and entire gateway snapshot restore. Tests cover duplicate and concurrent attempts, lost ACK, original approved-history changes/new operation ID, Host/installation/STATE/source/authority binding, revocation before and during send, revoked restart, wrong key, stale nonce, signed highwater and no automatic reopening.

## Required native owner and wiring — still NO-GO

This is a protocol design, **not** an independently protected installed service. `SyntheticExternalLedger` holds ordinary in-memory state; native code must NOT instantiate it or accept `test_sender`/`test_signer` injection from untrusted RPC. Source CI cannot demonstrate power-loss durability or prove installed authority.

1. **External separate rollback domain:** root-control/host-install must install a protected, independently administered monotonic ledger and signer with a root-only no-replacement admission process. Bind original independently authenticated Host/installation/STATE volume, source catalogue/receipt, original GitHub request history and root stage-once grant. Do not use the gateway's `generic-operation-send-intents`, STATE volume or the current-signing-key checkpoint alone as the owner. No synthesized empty highwater on an existing enrolled Host.
2. **Single native execution path:** root-control-owned protected sender must select immutable SSM target and argv itself from the approved operation. Host-deploy `generic_pipeline.advance` currently calls `host.submit_command` directly; before native authorization, that direct call MUST be routed behind the installed protected owner. A signed claim alone must not let the gateway send independently. No user/client callback injection, alternate recovery/admin path or local fallback. Require exact pinned owner source, binary/service identity, AF_UNIX `SO_PEERCRED`, and cryptographically verified current external signer/key.
3. **External durable claim transaction:** begin with independently authenticated current authority and original task, compare original operation to preapproved immutable mapping; persist and fsync/CAS claim in a distinct nonrollbackable authority BEFORE first SendCommand. Locks, revocation and send commit must share single monotonic order even across multiple gateway processes and reboot. Claim publication crash, lost ACK and command ID publication failure remain HOLD, never a second send.
4. **Source and policy verification:** map host-deploy PR18 `graphics_operation_send_intent._expected` to owner request, but derive Host, installation, STATE, authority epoch, original request SHA and root stage-once evidence independently of gateway-local JSON. Reject mismatch, source pin change, rotated/revoked authority, stale checkpoints or incomplete approved receipts.
5. **Native negative acceptance:** test whole gateway+STATE rollback, foreign Host/STATE, installation migration, old valid signing key after rotation, revoked epoch, absent issuer, substituted localhost socket/peer UID, forged old signed observation, dual process concurrent submit and cancellation, power loss before claim, power loss after claim but before SSM, lost ACK, reboot and failover with preserved claim, and original remote command-readback. No source-only fixture can attest these installed properties.

**Owner coordination:** root-control Regular independent source reviewer; host-deploy Regular prepares exact read-only envelope/consumer integration; host-install Regular owns protected installation and source/commit pin. Work/native acceptance must attest the separate genuine ledger and exact selected privileged sender. Do **not** merge or enable the path, submit a job, contact AWS/SSM or publish synthetic authority.
