## Source-implemented pieces

- `graphical_native_owner.ProtectedLedger` uses an installer-created, independently protected `0700` claim directory, preexisting stable `0600` file lock, `O_NOFOLLOW|O_EXCL`, fsync of irreversible `CLAIMED_UNCERTAIN` before SendCommand, terminal result sidecar and no duplicate send after lost ACK, torn local claim or process reconstruction.
- `graphical_owner_checkpoint.SeparateDurableCheckpoint` creates an irrevocable operation record **before** the ledger claim. The checkpoint and ledger are separate from gateway STATE; the real installer must also require distinct mounts and devices. Revocation takes both locks under the same owner critical section and commits checkpoint denial first. **These are durable file backends, not independently administered antirollback hardware/remote authority. Coherent rollback of both protected filesystems is not covered. Native gate remains NO-GO pending an independently nonrollbackable external highwater.**
- `SelectedOwner` verifies installer-pinned signed operator approval and original selected operation SHA inside its own admission path, rather than trusting gateway's precheck. It looks up command by installed ID, never by socket-provided text. Source test sender is supplied only by disposable offline unit test, not the fixed native executable.
- `graphical_owner_service` is a root-only, fixed-path, socket-activated executable requiring protected installed identity, distinct mounted root ledger/checkpoint/gateway volumes, `SO_PEERCRED` exact gateway UID/GID over `AF_UNIX SOCK_SEQPACKET`, and root-owned credential path via systemd `LoadCredential`. Its AWS SSM call uses explicit owner-only short-lived access key, secret and session token; **no boto3 default credential chain, IMDS fallback, caller script/target/document**. The script is root-only installer-written by immutable operation ID and independently hashes against preinstalled `script_sha256`.

## Source/native distinction

The source can be packaged and tested, but NO approved Host installation or credential exists and no service is enabled by these commits. The separate gateway cannot be granted SSM rights merely because the source is executable. An install must enforce `Deny SendCommand` on the gateway AWS principal and prove gateway cannot obtain owner credentials through /run/credentials, shared files or IMDS. For true antirollback it must independently attest a nonrollbackable checkpoint outside both gateway and owner volume rollback, including highwater at reboot.

A preflight is itself an SSM mutation; root owner must separately preapprove/fence a distinct preflight original operation, verify its result, then permit the corresponding stage. No `Host.command` direct bypass is allowed. Actual owner-preflight reconciliation, network transport, IAM proof, crash and reboot acceptance remain subsequent integration work. No AWS/SSM calls, keys, canonical STATE or production source pins changed.
