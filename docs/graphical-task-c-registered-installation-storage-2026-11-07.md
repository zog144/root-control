# Task C registered installation storage authority — 2026-11-07

## Decision and correction

The previous source derived the S3 checkpoint genesis/scope from `digest(scope_from_request(request))`. The request scope deliberately includes a catalogue SHA, source revision, approved original request identity, authority pin and approval SHA. These values become authentic **after** a future GitHub event and operator grant, while the protected storage backing and first checkpoint must be installed **before** that event. Requiring request-scope storage at installation creates a circular dependency and should not be used to claim an accepted service placement.

**Selected correction:** establish a separate v3 *installation storage authority* whose stable canonical identity is signed by the Host registry authority and bound to `host_id`, `host_fingerprint`, `registry_id`, `controller_id`, `target_identity_sha256`, `installation_id` and `state_volume_id`. No catalogue, pipeline lane, approval, source revision, request ID or operation ID is included in that persistent storage identity. Derive `installation_scope_sha256` only from the signed registered installation, **not** from a future request.

The independently operator-signed **storage-establishment approval** uses a different signature domain and covers exact S3 account/region/bucket/prefix, distinct writer and GetObject-only reader roles, deterministic *prospective* genesis hash, signed registry hash, installation scope, independently retained anchor identity, expiry and retention disposition of any uncertain original history. It cannot authorize any `SendCommand`, claim, revocation or specific Fonts operation.

## Exact source contracts

- `graphical_installation_storage_authority.py`: verify Ed25519 registry receipt under an independently pinned registry key, compute the stable installation scope, check the separately signed storage-establishment approval under the separately pinned operator key, and bind future owner requests to the registered Host/installation/STATE and registry IDs. The operation scope remains `digest(scope_from_request(request))`, and any explicit operator grant is still checked with `verify_original_operator_approval()`. No key, record or S3 genesis is generated by this module.
- `graphical_installation_storage_commit.py`: a separate signed and independently retained installer commitment records exact installation scope, authority hash, signed storage approval hash, three different filesystem UUIDs, mounted unit hashes, accepted time and independent anchor digest. It verifies storage approval **at the signed installation-commit time**, not as a reusable 15-minute operation token on every later reboot. A separate pinned installer key and externally retained commitment digest are required. Source receipt verification reports `runtime_storage_accepted=False`.
- `graphical_s3_installation_checkpoint.py`: the installation-scoped genesis uses its own v1 schema and exact registry digest. Append-only events use a globally unique operation ID, exact request SHA and separately calculated operation-scope SHA. A `revoke` event blocks **that request scope** only, not future unrelated requests. Prior request events remain hash-checked and globally duplicate-checked even when their old approvals are no longer in the latest owner's active registry. Active claims must exactly match the current signed request map. Missing genesis, AccessDenied or ambiguous next sequence, changed hash-link, duplicate ID, writer conflict and lost ACK HOLD. No automatic retry, deletion, ListBucket, remote initialization or SSM call.
- `graphical_task_c_native.py`: an **explicit v3 runtime selection** reads fixed root-protected registry, authority, approval, signed commit and external anchor paths, checks separate mounts, signer pins, exact service/Host/STATE and S3 tuple, and creates `S3InstallationCheckpoint` with only the selected active request operations. The original historical v2 request-bound constructor remains separate and unchanged; v2 S3 history cannot be relabeled as v3. The runtime continues verifying original operator/issuer evidence and protected owner claims before send. A new v3 source branch is **not** permission to activate the installed service.
